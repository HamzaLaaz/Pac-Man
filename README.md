# Pac-Man

## Description

A complete, playable recreation of the classic **Pac-Man** arcade game in
Python, built with object-oriented programming and the MLX graphical
library. The player moves Pac-Man through a procedurally generated maze,
eating pacgums and super-pacgums while avoiding four autonomous ghosts
(Blinky, Pinky, Inky, Clyde), each with its own chase behavior. Eating a
super-pacgum makes the ghosts edible for a short time, letting the player
eat them back for bonus points. The game runs through at least 10 levels
of increasing maze size, keeps score and lives between levels, and saves
the top 10 scores to a persistent highscore table.

Key features:

- A custom JSON configuration file (with comment support) driving level
  sizes, lives, scoring and timing.
- Maze generation delegated to an external "A-Maze-ing" package
  (`mazegenerator`), used as-is per the assignment's rules.
- A persistent, validated top-10 highscore table.
- A full UI: main menu, in-game HUD, pause menu, instructions screen,
  highscores screen, and win/game-over screen with name entry.
- A cheat mode (invincibility, level skip, ghost freeze, extra lives,
  speed boost, timer reset) for easier manual testing/review.
- Fully typed codebase: `flake8` and `mypy --strict` both pass clean.

## Instructions

### Requirements

- Python 3.10 or later (developed and tested with Python 3.14).
- [`uv`](https://docs.astral.sh/uv/) for dependency management.
- The `mlx` and `mazegenerator` wheels bundled in this repository
  (`mlx/` and `mazegenerator/`) are installed automatically by `uv sync`.

### Setup and run

```sh
make install        # installs dependencies with uv
make run             # runs the game with the default config (src/config.json)
make run CONFIG=path/to/your_config.json   # run with a custom config file
```

The game can also be run directly from the repository root, taking
exactly one argument (the path to a JSON config file), as specified by
the subject:

```sh
python3 pac-man.py src/config.json
```

Any problem with the config file (missing file, invalid JSON, bad values)
is reported as a clear warning on stdout and falls back to safe defaults
— it never crashes with a Python traceback.

### Other Makefile targets

| Target        | Purpose                                                       |
|----------------|----------------------------------------------------------------|
| `make debug`   | Run the game under Python's `pdb` debugger.                   |
| `make lint`    | Run `flake8` and `mypy` (project-mandated flags).              |
| `make lint-strict` | Run `flake8` and `mypy --strict` (stricter, optional check). |
| `make clean`   | Remove `__pycache__`, `.mypy_cache` and `.pytest_cache`.        |
| `make fclean`  | `clean` plus remove the virtual environment (`.venv`).         |

### Controls

- **Arrows** or **WASD**: move Pac-Man.
- **P** or **ESC**: pause the game.
- **C** (in game): toggle cheat mode, then:
  `N` skip level, `I` invincibility, `F` freeze ghosts, `L` extra life,
  `O` speed boost, `T` reset the level timer.

## Configuration

The game is configured through a single JSON file, passed as the only
command-line argument (see `src/config.json` for the default). In
addition to standard JSON, the parser (`src/config.py`) also accepts
comments: lines starting with `#` or `//`, and `/* ... */` blocks, are
stripped before parsing — comments inside quoted strings are left alone.

Any missing, malformed, or out-of-range value is clamped to a safe
default and logged as a warning; unknown keys are ignored. Nothing in
the config file can crash the game.

Structure (all keys optional — missing ones fall back to defaults):

| Key | Description | Default |
|-----|--------------|---------|
| `highscore_filename` | File the highscore table is saved to. | `highscores.json` |
| `game_settings.level_max_time` | Seconds allowed per level (60–3600). | `90` |
| `game_settings.seed` | Seed for level 1's maze (integer ≥ 0). | `42` |
| `game_settings.levels` | Array of `{width, height}` per level (14–29 each). At least 10 levels; missing ones are padded with sensible defaults. | 10 levels, 15×15 up to 25×25 |
| `player.lives` | Starting lives (1–99). | `3` |
| `score.pacgum` | Points per pacgum eaten. | `10` |
| `score.super_pacgum` | Points per super-pacgum eaten. | `50` |
| `score.ghost` | Points per edible ghost eaten. | `200` |

## Highscore

Highscores are persisted as a JSON file (`highscores.json` by default,
see `src/highscores.py`). This format was chosen because it requires no
extra dependency, is human-readable, and matches the JSON config already
used elsewhere in the project.

- The table keeps the **top 10** scores, sorted highest first.
- A name is cleaned to at most 10 characters, alphanumeric and spaces
  only, before being stored (invalid characters are dropped).
- Scores are stored as non-negative integers.
- The table is loaded once at startup and re-saved every time a new
  score is added; a missing file, invalid JSON, or malformed entries are
  handled gracefully (bad entries are skipped, not a crash).
- The player is prompted to enter their name on the win/game-over screen,
  and the table is shown from the main menu.

## Maze Generation

Per the assignment's rules, the project does **not** implement its own
maze generator. Instead it depends on the external `mazegenerator`
package (the "A-Maze-ing" package assigned to this group), bundled as a
local wheel in `mazegenerator/` and declared as a dependency in
`pyproject.toml`.

- `src/screens/game_screen.py` calls `MazeGenerator(size=(width, height),
  perfect=False, seed=...)` as-is, without modifying the package.
- `perfect=False` is required by the subject so the generator produces
  Pac-Man-style corridors (loops) instead of a perfect, single-path maze.
- The first level always uses the config's `seed` so it is reproducible;
  every following level passes `seed=0`, which the package treats as
  "random", so later levels differ between runs.
- If the generator fails or returns a maze of the wrong size, the error
  is caught and turned into a clear `RuntimeError` instead of crashing.

## Implementation

- **Language/tooling**: Python 3.14, dependency management via `uv`,
  graphics via the MLX library.
- **Typing**: the whole codebase is annotated and passes both
  `mypy` (mandatory flags) and `mypy --strict` with zero errors; `flake8`
  is clean as well (see `make lint` / `make lint-strict`).
- **Error handling**: config loading, maze generation, and level creation
  are all wrapped so that a failure is reported with a clear message and
  the game degrades gracefully (falls back to defaults, skips the level,
  etc.) instead of crashing.
- **Game loop**: a single MLX loop hook in `src/main.py` drives a small
  state machine (`menu`, `game`, `pause`, `end`, `highscores`,
  `instructions`) and dispatches rendering/input to the screen that is
  currently active.

## General Software Architecture

```
pac-man.py                   # root entry point (python3 pac-man.py config.json)
src/
├── main.py                 # game-state machine, MLX hooks
├── config.py                # JSON+comments config parsing & validation
├── highscores.py             # persistent top-10 highscore table
└── screens/
    ├── mlx_class.py          # thin wrapper around the MLX window/instance
    ├── constants.py           # shared constants (colors, keys, sizes...)
    ├── text.py                # cached BDF text rendering helper
    ├── main_menu.py           # main menu screen (+ Button helper)
    ├── pause_screen.py        # pause menu
    ├── instructions_screen.py # controls/rules/cheats screen
    ├── highscores_screen.py   # top-10 table screen
    ├── end_screen.py          # win/game-over screen with name entry
    ├── game_screen.py         # core gameplay: maze, HUD, timer, collisions
    ├── ghost_ai.py             # GhostAI: per-ghost target + BFS pathfinding
    └── classes/
        └── entities.py         # Pacman, Pacgums (dots), Ghost
```

Relationships:

- `pac-man.py` is a thin root-level shim: it puts `src/` on `sys.path`
  and delegates to `src/main.py`'s `main()`, so the game can be launched
  as `python3 pac-man.py config.json` straight from the repository root.
- `main.py` owns one instance of every screen and a `GameScreen | None`
  for the currently running level; it never draws anything itself, it
  only switches between screens and forwards mouse/keyboard events.
- `GameScreen` is the hub for a single level: it owns the `Pacman`,
  `Pacgums` and the four `Ghost` instances, builds the maze image from
  `mazegenerator`'s output, and drives one frame of gameplay (movement,
  collisions, scoring, win/lose checks) per call to `render()`.
- Each `Ghost` delegates its decision-making to its own `GhostAI`
  instance, which picks a target tile (depending on the ghost's name and
  whether it is edible) and finds a path to it with BFS.
- `Pacman`, `Pacgums` and `Ghost` all go through `MlxClass` to talk to
  the MLX library, so no screen touches the raw library directly except
  through that wrapper.
- `Config` and `Highscores` are standalone, UI-agnostic classes: `main.py`
  loads them once at startup and passes them down to the screens that
  need them (`GameScreen`, `EndScreen`, `HighscoresScreen`).
